# معيار ونموذج التقارير الموحد للتحليلات والسيو (Reporting Schema & Governance)
## شركة مشعل بادغيش للمحاماة والاستشارات القانونية
**الإصدار:** 1.0.0  
**تاريخ الاعتماد:** 26 أكتوبر 2026  
**الغرض:** تحديد نموذج موحد وثابت لإعداد تقارير الأداء الدوري (SEO, Analytics, GEO/AEO) لضمان اتساق المقاييس، ودقة المقارنات، ومنع اختلاق أو تضارب البيانات.

---

## 1. فلسفة المعيار ومبادئ النزاهة الإحصائية

1. **الصرامة في إسناد الأدلة (Evidence-Based Only):** لا يُدرج أي رقم أو مؤشر في أي تقرير ما لم يكن مستخرجاً من واجهة برمجة تطبيقات رسمية (Official API)، أو فحص خادم مباشر (Live HTTP Assertions)، أو سجل استعلامات موثق.
2. **حظر اختلاق البيانات والتعويض التخميني (Zero Imputation Policy):** في حال تعذر الوصول إلى منصة أو مقياس (مثل توقف الحصة أو نقص الصلاحية)، يُسجل المقياس صراحة كـ `UNAVAILABLE` أو `BLOCKED` مع ذكر السبب التقني، ويُحظر تماماً وضع تقديرات أو أرقام افتراضية.
3. **الفصل بين الحقائق والاستنتاجات والتوصيات:** كل تقرير يجب أن يفصل هيكلياً بين:
   - **الواقع المرصود (Observed Facts):** الأرقام الخام وحالات الكود.
   - **التحليل الفني (Inferences):** قراءة الأسباب الجذرية والعلاقات بين الأرقام.
   - **التوصيات التنفيذية (Recommendations):** الخطوات المقترحة الخاضعة للاعتماد.
4. **حماية البيانات الحساسة والأسرار (No PII / Secrets Exposure):** يُمنع إدراج مفاتيح الوصول (Tokens, API Keys, Service Account Credentials) أو بيانات العملاء الشخصية (الأسماء، الهواتف، نصوص الاستشارات) داخل ملفات Git أو التقارير المرفوعة للمستودع.

## 3. قاموس المقاييس الموحد وتعريفاتها (Metrics Dictionary)

### أ. مقاييس Google Analytics 4 (سلوك المستخدمين والزيارات)

| اسم المقياس المعتمد | الرمز البرمجي في API | التعريف الإحصائي الدقيق | شروط الاعتماد والمقارنة |
| :--- | :--- | :--- | :--- |
| **المستخدمون النشطون** | `activeUsers` | عدد المستخدمين الفريدين الذين خاضوا جلسة متفاعلة أو قضوا زمناً في الواجهة. | لا تجمع عبر الصفحات لمنع التكرار (Non-additive across pages). |
| **إجمالي الجلسات** | `sessions` | فترات التفاعل المتواصلة للمستخدمين على الموقع (تنتهي بعد 30 دقيقة من الخمول). | تقاس للجلسات المكتملة فقط. |
| **مشاهدات الصفحات** | `screenPageViews` | إجمالي عدد مرات تحميل وعرض صفحات الموقع (يشمل تكرار المشاهدة للمستخدم الواحد). | تقبل الجمع المباشر عبر المسارات. |
| **الجلسات المتفاعلة** | `engagedSessions` | الجلسات التي استمرت أكثر من 10 ثوانٍ، أو شهدت حدث تحويل، أو مشاهدتي صفحة فأكثر. | المقياس المعياري لجودة الزيارات. |
| **معدل التفاعل** | `engagementRate` | النسبة المئوية للجلسات المتفاعلة مقسومة على إجمالي الجلسات (`engagedSessions / sessions`). | يجب حسابها من إجمالي الفترتين ولا تحسب كمتوسط حسابي للنسب. |
| **القنوات التسويقية** | `sessionDefaultChannelGroup` | التصنيف المعياري لجوجل لمصادر الزيارات (Direct, Organic Search, Organic Social, AI Assistant). | يجب توثيق أي جلسات تقع ضمن Unassigned. |

### ج. تصنيفات تقرير التغطية والفهرسة (Indexation & Coverage Taxonomy)

| الحالة في Search Console | المعنى التقني | التفسير السليم لحالة الموقع |
| :--- | :--- | :--- |
| **Indexed** | الصفحة خضعت للزحف والفهرسة وتظهر في محرك البحث. | الحالة المثالية لصفحات الخدمات والمقالات المستهدفة. |
| **Page with redirect** | صفحة التمسها جوجل وأعادت تحويلاً 301 إلى مسار آخر. | **حالة صحية وطبيعية** للروابط الموروثة والامتدادات القديمة (`.html`). |
| **Not found (404)** | صفحة طلبها جوجل وأعادت كود HTTP 404 صريح. | **سلوك سليم** للصفحات الملغاة التي لا تملك بديلاً؛ يُفحص فقط لمنع سقوط صفحات ذات قيمة. |
| **Discovered — currently not indexed** | رصد جوجل الرابط (عبر خريطة الموقع مثلاً) لكنه لم يجدوله للزحف الفوري بعد. | **مرحلة انتظار طبيعية** للمواقع الناشئة والمحتوى المستحدث؛ تتطلب تعزيز الروابط الداخلية. |
| **Crawled — currently not indexed** | زحف جوجل للصفحة وقرأ محتواها لكنه قرر استبعادها مؤقتاً من الفهرس. | مؤشر جودة أو تشابه محتوى يتطلب تدقيقاً تحريرياً. |
| **Redirect error** | فشل التحويل بسبب حلقة مفرغة (Loop) أو سلسلة طويلة أو رابط معطوب. | **خلل فني خطير** يجب أن تكون قيمته صفراً دائماً في الموقع. |
| **Alternate page with proper canonical** | صفحة مطابقة لصفحة أخرى تعترف بصفحة كانونيكال بديلة. | فحص لمنع تضارب روابط الـ Desktop والـ Mobile أو تكرار البارامترات. |

## 4. شروط المقارنة السليمة وفترات السحب (Fair Comparison Rules)

1. **فترات زمنية متساوية وكاملة (Equal & Complete Windows):**
   - المعيار المعتمد للمراجعات الشهرية هو **آخر 28 يوماً مكتملة** مقارنة بـ **الـ 28 يوماً السابقة مباشرة** (28-day rolling window).
   - تجنب المقارنات بين فترات غير متطابقة الأيام (مثل مقارنة 28 يوماً بـ 30 يوماً).
2. **مراعاة التأخير الزمني (Time-Lag Synchronization):**
   - بيانات GA4 تُسحب بفترة تنتهي عند (T-1) لضمان اكتمال معالجة بيانات اليوم السابق.
   - بيانات GSC تُسحب بفترة تنتهي عند (T-3) لتفادي الانخفاض الوهمي في الأرقام الناتج عن تأخر معالجة Search Console لآخر 72 ساعة.
3. **التجميع الدقيق للمسارات (Path Normalization):**
   - عند إعداد تقارير أكثر الصفحات زيارة في GA4، يجب التجميع ببُعد `pagePath` المجرد، أو توضيح بُعد `pageTitle` إن أُدرج لمنع التكرار الظاهري للمسار نفسه (مثل ظهور مسار `/contact` بعدة عناوين).

## 5. التمييز الصارم في أداء الذكاء الاصطناعي (GEO / AEO Attribution)

يجب الفصل التام وعدم الخلط بين التصنيفات الأربعة التالية:

1. **حركة البحث العضوي التقليدي (Organic Search):** نقرات وزيارات ناتجة عن نقر المستخدم على روابط محرك بحث جوجل أو بينج القياسية.
2. **إحالات وكلاء الذكاء الاصطناعي في GA4 (AI Assistant Referrals):** زيارات حقيقية للموقع قام فيها المستخدم بالنقر على رابط مدرج داخل محادثة مع أدوات مثل ChatGPT أو Perplexity أو Copilot.
3. **ميزات البحث التوليدي في GSC (Search Generative Features):** ظهور الموقع أو النقر عليه من داخل مقتطفات وميزات الذكاء الاصطناعي التوليدي في صفحات بحث جوجل (AI Overviews)، وتُقاس حصراً عبر بُعد `searchAppearance`.
4. **السلطة الدلالية ومحركات الإجابة غير القابلة للقياس المباشر (Zero-Click AEO Visibility):** قراءة نماذج الذكاء الاصطناعي لبيانات الكيان وتضمينها في الإجابات دون توليد نقرة، وتُدعم فنيّاً عبر جودة الـ JSON-LD ونصوص الـ Markdown المهيكلة عبر ترويسة `Accept: text/markdown` دون ادعاء وجود أرقام نقرات غير مثبتة لها.

## 6. آلية كشف التغييرات والربط بالتقارير السابقة (Audit Lineage & Change Detection)

1. **الترقيم الثابت للمشكلات (Unique Finding IDs):**
   - تحمل كل مشكلة معرفاً ثابتاً لا يتغير عبر الجولات: `FND-001`, `FND-002`, ...
   - لا يُعاد استخدام المعرف لمشكلة جديدة، ولا تُفرخ مشكلة واحدة في معرفات متعددة.
2. **دورة حياة الحالة الموحدة (Standard Lifecycle States):**
   - `OPEN`: مشكلة مؤكدة لم يبدأ العمل عليها.
   - `INVESTIGATING`: مشكلة قيد البحث وجمع الأدلة الإضافية.
   - `READY_FOR_REVIEW`: تم رفع التوصية أو الحل وينتظر المراجعة والاعتماد البشري.
   - `APPROVED`: تم اعتماد التوصية ومجدولة للتنفيذ البرمجي.
   - `FIXED_NOT_VERIFIED`: نُفذ التعديل محلياً ولكن لم يتم التحقق منه في خادم الإنتاج الحي.
   - `VERIFIED_IN_PRODUCTION`: تم التحقق الفعلي بالدليل الحي على خادم الإنتاج.
   - `WONT_FIX`: تم استبعاد المشكلة لعدم انطباقها أو لأسباب استراتيجية موثقة.
   - `BLOCKED`: تعذر التقدم لوجود مانع خارجي (مثل حصص API أو قرارات المالك).
3. **سجل الفروقات الدوري (Delta Tracking):**
   - يقارن كل تقرير جديد سجل `FINDINGS_REGISTER.csv` للجولة السابقة، ويوثق صراحة ما تم إغلاقه وما استجد وما بقي معلقاً.
